# CHIRON web: design contract

System: `linear.app` from ~/.config/design-md (near-black product canvas, tiered surfaces, hairline borders, a single accent), adapted with one accent (the selected network's color) and semantic status colors only to a ledger page. Tokens live in `src/tokens.css`; components read only tokens.

1. **Direction:** an operator console for one agent trading account. Near-black canvas, three surface tiers, 1px hairlines. The primary accent is used only for the primary action, focus and the network dot beside the block stamp, and it is the selected network's own color (Robinhood Chain lime #c3f53c, Arbitrum blue #28a0f0; #5e6ad2 fallback), so the page says which chain it reads before any text does. Status follows the four-tone semantic system below (ok mint, warn amber, bad red, neutral); there is no second accent.
2. **Fonts:** Archivo Variable (display + body, self-hosted via @fontsource-variable/archivo, wdth axis) and IBM Plex Mono 400/500 (@fontsource/ibm-plex-mono) for addresses, hashes, amounts and block numbers. No Inter/system face: Archivo's semi-condensed width gives the metrics a tighter, instrument-panel look than Linear's Inter.
3. **Palette (CSS variables):** --canvas #08090a, --surface-1 #0f1011, --surface-2 #141516, --surface-3 #1b1c1e, --hairline #23252a, --hairline-strong #34343a, --ink #f7f8f8, --ink-muted #d0d6e0, --ink-subtle #989da6, --accent per network ([data-chain] in tokens.css: #c3f53c / #28a0f0, fallback #5e6ad2), --ok #3ec6a8 (mint, kept clear of the lime accent), --warn #e3b341, --bad #f2555a; chain dots RHC #c3f53c, Arbitrum #28a0f0.
4. **Spacing / type:** 4px base: 4 8 12 16 24 32 48 64. Type scale 12/13/14/16/20/28/44 (13 is chart text only); gate values 20 mono tabular; labels sentence case, never uppercase-transformed. Radius 6 (controls), 10 (sheet and panels), pill for chips. One shadow only for real elevation (wallet menu, tx toast).
5. **Layout:** top bar (wordmark, chain switch, wallet) → one sheet that leads with the primary metric (trades the agent executed, 64px mono) and what it means (calls blocked, spend those blocks stopped, cap left today), under a trust row (network badge with chain id, link to the on-chain TDX admission with its timestamp); then the headline + the single primary action ("Recheck every receipt", with its verdict in place), then the signature strip: the four checks every call passes (quote, code, caps, receipt) joined by a rail, each with its live state and how many refused calls were stopped at that step (refusals mapped by custom error), then the caps chart on the same sheet → ledger of activity on the canvas (left) and a sticky Policy panel with caps (right) → owner controls as a collapsed disclosure row. Under 1000px one column with Activity before Policy.

## Status color system (v3: BACKED v3 reference, Web3-grade pass)
| Tone | Token | Means | Used on |
|---|---|---|---|
| ok | --ok #3ec6a8 mint | done: trade executed (also after owner approval), receipt verified, account open | chips, chart "executes" zone, filled marks (owner-approved trades are hollow mint) |
| warn | --warn #e3b341 amber | waiting on the owner: proposed, approval zone | chips, chart approval line and zone |
| bad | --bad #f2555a red | refused call or failed receipt check | chips, refused row tick, chart cap line and marks |
| neutral | --ink-muted on --surface-3 | admin and configuration: revoked, withdrawn, rejected, none | chips |
Primary accent = the network's color (action, focus, network dot). Every chip carries its word; color never stands alone.

## Chart
Signature: "Every trade attempt against the caps", on the sheet under the four checks. One axis in the lead token, three zones (executes / owner approves / reverts) split by the approval line (amber dashed) and the per-trade cap (red). Each call is a numbered mark in its outcome lane (executed, owner-approved, refused) marks stay at their true amount, and calls in one lane closer than 18px share one mark with a "+k" count, so no mark covers another; the numbered list under the chart gives each mark its exact amount, outcome, distance past a line it just crossed, and the refusal reason, so nothing depends on hover. Drawn at the container's real pixel width (ResizeObserver): chart text stays 13px and mark numerals 12px on phones, where zone names move into a text key.

## Type scale and contrast (WCAG 2.1 AA)
Scale 12 / 13 (chart) / 14 / 16 / 20 / 28 / 44; 12px only for mono metadata (hashes, times). --ink-subtle raised to #989da6. `design-research/tools/contrast.cjs` measures every rendered text node (HTML and SVG) on both chains at 1440 and 390 against its composited background and fails below 4.5:1 (3:1 for large text); disabled controls excluded per WCAG 1.4.3.

## Web3-grade rules (kamal, Oct 11)
Main job: what the agent traded, what it was blocked from, and why. References: Hyperliquid's layout zones (header / primary figures / working area / ledger), Aave's prominence of risk (blocked calls sit beside the headline number, not below the fold).
1. Lead with the primary metric (trades executed). 2. Every number states what it means: cap used and left today, blocked calls and the spend they stopped, refusals counted per check, each chart mark with outcome and reason. 3. Semantic colors plus one accent only. 4. A plain-language "What you sign" summary sits above every signing button (deposit/withdraw, caps, code approval, proposal approve/reject, create account). 5. Trust signals: network badge with chain id, admission tx link with timestamp, explorer link and time on every row, block stamp.
